Use it when someone says "summarize this thread", "write a summary", "digest these notes", "tl;dr", "catch me up", "what did we decide", or "recap this call" and pastes or points to the text to condense.

Read everything the user gave you, then write a summary that someone who was not there can act on. If the source is a file or a long paste, read all of it before you write. Do not summarize from the first few lines.

## What to Extract

1. **Key points** — the facts and updates that matter. Drop small talk, repeats, and tangents.
2. **Decisions** — what was agreed, and who decided if it is stated.
3. **Open questions** — what is still unresolved or blocked, and who needs to answer.
4. **Action items** — one line per task, each with an **assignee**. If no one was named, write **Unassigned**. If a due date was stated, add it.

Only include what the source says. Do not guess at decisions, owners, or dates. If something is ambiguous, say so in a few words.

## Format

- Use short bullet points. One idea per bullet.
- **Bold** the words a skimmer needs: names, decisions, dates, numbers, and blockers.
- Use these section headings, in this order: **Key points**, **Decisions**, **Open questions**, **Action items**. Leave out a section that has nothing in it.
- Write action items as: **Assignee** — task (due date if given).
- Put a one-line **tl;dr** at the top when the source is long or the user asked for one.

## Density

- Keep the summary far shorter than the source. Aim for the fewest words that keep every decision and action item.
- No filler: no intro such as "Here is a summary", no closing offer, no restating the request.
- Use plain, direct English. Keep names, numbers, and technical terms exactly as written in the source.
